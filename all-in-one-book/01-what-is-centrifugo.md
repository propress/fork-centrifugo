# 第1章 Centrifugo 是什么？

> **阅读目标**：理解 Centrifugo 解决什么问题、核心架构是什么、适合哪些场景

---

## 1.1 一句话理解 Centrifugo

**Centrifugo 是一个独立部署的实时消息推送服务器**，它让你的后端应用能够即时地把消息推送给所有在线的客户端（浏览器、手机 App 等）。

用最通俗的话说：

> 你的后端写好数据 → 调一下 Centrifugo 的 API → 所有订阅了这个频道的用户立刻收到消息

**不需要**你自己去管理 WebSocket 连接、心跳、断线重连、消息缓存等复杂逻辑。

## 1.4 关键特性一览

| 特性 | 说明 | 你需要关心吗？ |
|------|------|----------------|
| **多传输协议** | WebSocket、SSE、HTTP 流、gRPC、WebTransport | ✅ 一般用 WebSocket |
| **频道订阅** | 客户端订阅频道，收到该频道的消息 | ✅ 核心概念 |
| **消息历史** | 频道可以保留最近 N 条消息 | ✅ 聊天场景必用 |
| **断线恢复** | 客户端断线后自动补发遗漏消息 | ✅ 很实用 |
| **在线状态** | 查看谁在线，收到上下线通知 | ✅ 协作场景 |
| **JWT 认证** | 用 JWT token 验证客户端身份 | ✅ 生产必须 |
| **代理认证** | 把认证请求转发给你的后端 | 🟡 高级用法 |
| **HTTP/gRPC API** | 后端通过 API 发布消息、管理连接 | ✅ 核心使用方式 |
| **Redis 扩展** | 多个 Centrifugo 节点通过 Redis 同步 | 🟡 上线后关注 |
| **消息消费者** | 从 Kafka/PostgreSQL 等消费消息 | 🔴 高级场景 |
| **Admin UI** | 内置 Web 管理界面 | ✅ 开发调试必用 |
| **Prometheus** | 暴露监控指标 | 🟡 生产环境 |

## 1.5 适合什么场景？

### ✅ 非常适合

| 场景 | 为什么适合 |
|------|-----------|
| **即时聊天** | 频道 = 聊天室，消息历史 + 断线恢复完美匹配 |
| **实时通知** | 服务端推送通知到指定用户，用个人频道 |
| **实时数据看板** | 股票行情、监控面板、实时数据可视化 |
| **协同编辑** | 在线状态 + 实时同步非常方便 |
| **多人游戏** | 低延迟消息分发 + 频道隔离 |
| **直播互动** | 弹幕、点赞、互动等实时消息 |
| **IoT 数据流** | 设备数据实时推送到前端 |

### ⚠️ 不太适合

| 场景 | 原因 |
|------|------|
| **持久化消息队列** | Centrifugo 的历史消息是临时缓存，不是持久存储 |
| **离线消息推送** | 它是在线实时推送，不处理用户离线后的消息 |
| **复杂消息路由** | 不支持复杂的消息过滤和路由规则（PRO 版有一些） |
| **文件传输** | 不适合传大文件，适合传小的 JSON/二进制消息 |

## 1.8 技术架构深入理解

### 消息流转过程

让我们用一个聊天场景来理解消息是怎么流转的：

```
步骤1: 用户A 在浏览器发送聊天消息
    浏览器 → HTTP POST → 你的后端

步骤2: 你的后端处理业务逻辑（保存到数据库等）
    你的后端 → INSERT INTO messages → 数据库

步骤3: 你的后端通知 Centrifugo 推送消息
    你的后端 → POST /api/publish → Centrifugo
    请求体: { "channel": "chat:room_42", "data": {"text": "Hello!"} }

步骤4: Centrifugo 把消息推送给所有订阅了该频道的客户端
    Centrifugo → WebSocket → 用户B 的浏览器
    Centrifugo → WebSocket → 用户C 的手机
    Centrifugo → WebSocket → 用户D 的浏览器
    ...
```

```
时间线：

用户A                 你的后端               Centrifugo            用户B/C/D
  │                      │                      │                    │
  │── POST /send ───────▶│                      │                    │
  │                      │── 保存消息到 DB ─────▶│                    │
  │                      │── POST /api/publish ─▶│                    │
  │                      │                      │── WebSocket 推送 ──▶│
  │                      │◀── 200 OK ───────────│                    │
  │◀── 200 OK ──────────│                      │                    │
  │                      │                      │                    │
  延迟：通常 < 100ms     │                      │                    │
```

### 🔑 理解"频道"这个概念

频道（Channel）是 Centrifugo 最核心的概念，类似于：
- 微信群聊里的 **群**
- Redis 的 **PUB/SUB 频道**
- 消息队列的 **Topic**

```
频道示例：

"chat:room_42"          ← 聊天室 42 的消息
"user:1001"             ← 用户 1001 的个人通知
"stock:AAPL"            ← 苹果股票的行情
"game:match_789"        ← 游戏对局 789 的状态
"dashboard:monitoring"  ← 监控面板的数据
```
